# دوابنو: دليل التسليم والتشغيل

هذا الدليل لمن سيتولى تشغيل دوابنو بعد انتهاء البناء. يشرح ما هو موجود، ومن يملك ماذا، وكيف يُعاد الإعداد من الصفر، وكيف تُنفَّذ المهام اليومية، وما الذي لا يزال تجريبيًا. لا توجد أي كلمات سر أو مفاتيح سرية في هذا الملف ولا في المستودع.

النسخة الإنجليزية: `HANDOVER.md`. خطة نقل الحسابات إلى اسم الشركة: `docs/ACCOUNT-TRANSFER.md`. آخر تحديث: 2026-11-06.

## 1. ما هو دوابنو
ثلاث صفحات ويب ثابتة وقاعدة بيانات:

| الجزء | المجلد | العنوان بعد الاستضافة | الوصف |
|---|---|---|---|
| الموقع | `web-v2/` | `/` | موقع لمقارنة الأسعار يبدأ بالبحث (عربي وإنجليزي) |
| تطبيق الجوال | `app-v2/` | `/app/` | شاشات التطبيق بحجم الجوال، بالبيانات والحسابات نفسها. وهو أيضًا الأساس الذي يعتمد عليه تطبيقا iPhone وAndroid |
| لوحة الإدارة | `admin-v2/` | `/admin/` | المنتجات والمتاجر والكوبونات والأسعار والفريق وسجل النشاط |
| قاعدة البيانات والخلفية | `backend/` | Supabase (سنغافورة) | الجداول وتسجيل الدخول وقواعد الوصول والمستورد والاختبارات |

تتصل الصفحات الثلاث مباشرة بـ Supabase من متصفح الزائر باستخدام مفتاح **عام**. لا يوجد خادم خاص بنا. وقواعد من يستطيع رؤية ماذا أو تعديل ماذا تفرضها قاعدة البيانات نفسها (أمان مستوى الصف)، وليس الصفحات.

```
 متصفح الزائر / المدير ──(مفتاح عام + رمز دخول المستخدم)──► Supabase (Postgres + تسجيل الدخول)
                                                                 ▲
 GitHub Actions (يوميًا) ──(مفتاح الخدمة)── المستورد: أسعار المتاجر ← الأسعار، رسائل التنبيه (Resend)
 GitHub Actions (أسبوعيًا) ── نسخة احتياطية مشفّرة لقاعدة البيانات
```

## 3. الأسرار: ما الموجود وأين يُحفظ
لا تضع أيًّا من هذه في المستودع ولا في `config.js` ولا في المحادثات.

| الاسم | ما هو | أين يُحفظ |
|---|---|---|
| عنوان المشروع والمفتاح العام (publishable) | **عام بطبيعته** | ملف `assets/config.js` في كل من المجلدات الثلاثة |
| `SUPABASE_URL` و`SUPABASE_SERVICE_KEY` | وصول كامل لقاعدة البيانات (يتجاوز كل القواعد) | أسرار GitHub (المستورد والتنبيهات) |
| `RESEND_API_KEY` و`ALERT_FROM` و`SITE_URL` | إرسال رسائل التنبيه؛ عنوان المرسل؛ عنوان الموقع | أسرار GitHub |
| `SUPABASE_DB_URL` و`BACKUP_PASSPHRASE` | اتصال النسخ الاحتياطي (session pooler) وعبارة تشفيره | أسرار GitHub |
| `CLICK_SALT` | نص عشوائي لتشفير هوية الزائر في تتبع النقرات | سر دالة Supabase |
| `GEMINI_API_KEY` و`GEMINI_API_KEY_2` و`GEMINI_MODEL` | البحث بالصورة | أسرار دوال Supabase |
| `FCM_SERVICE_ACCOUNT_JSON` و`GOOGLE_SERVICES_JSON_B64` | إشعارات Android | أسرار GitHub |
| `APPLE_TEAM_ID` و`ASC_KEY_ID` و`ASC_ISSUER_ID` و`ASC_KEY_P8` و`APNS_KEY_P8` و`APNS_KEY_ID` | بناء ورفع تطبيق iPhone وإشعاراته | أسرار GitHub |
| `ANDROID_KEYSTORE_B64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD` | توقيع تطبيق Android لمتجر Google Play | أسرار GitHub (لم تُنشأ بعد) |
| مفاتيح الخلاصات (مثل `FEED_NOON_KEY`) | بيانات دخول خلاصة متجر | سر في GitHub، ويُشار إليه في عنوان الخلاصة بالشكل `${FEED_NOON_KEY}` (يجب أن تبدأ أسماء هذه المفاتيح بـ `FEED_`) |

إذا انكشف أي سر، فبدّله (القسم 7) قبل أي شيء آخر.

## 4. الإعداد من الصفر (مشروع جديد)
1. **مشروع Supabase:** مشروع جديد. المنطقة الحالية سنغافورة (Southeast Asia). في SQL Editor شغّل بالترتيب ملفات `backend/supabase/migrations/` من `0001` حتى آخر رقم موجود، ثم ملفات البيانات في `backend/supabase/seed/` بالترتيب الرقمي (البيانات الأولية للكتالوج؛ تُترك عند ربط خلاصات حقيقية).
2. **أول مدير:** يسجّل ذلك الشخص حسابًا في الموقع، ثم شغّل أمر SQL الموجود في `backend/README.md` (قسم "Making the first admin").
3. **ربط الصفحات:** ضع عنوان المشروع والمفتاح العام في `web-v2/assets/config.js` و`app-v2/assets/config.js` و`admin-v2/assets/config.js` (القيم نفسها في الثلاثة).
4. **إعدادات تسجيل الدخول في Supabase** (Authentication):
   - URL Configuration: عنوان الموقع (Site URL) = العنوان الحقيقي `https://doabno.com`؛ وعناوين إعادة التوجيه (Redirect URLs) = العنوان نفسه مع `/**` (و`/app/**`).
   - البريد: أبقِ "Confirm email" **مفعّلًا**. فعّل **SMTP مخصصًا** عبر Resend، لأن مرسل Supabase المدمج محدود بعدد قليل من الرسائل في الساعة.
5. **الاستضافة (Cloudflare Pages):** المشروع اسمه `doabno` ويُنشر برفع مباشر بأداة Wrangler (ليس مربوطًا بـ Git). من مجلد المستودع:
   ```
   node scripts/build-site.js
   npx wrangler pages deploy dist --project-name doabno --branch main
   ```
   الأمر الأول يبني مجلد `dist`، والثاني ينشره. يجب تسجيل الدخول إلى Cloudflare بحساب الشركة (`npx wrangler login`). النطاق `doabno.com` مربوط بالمشروع من لوحة Cloudflare، قسم Custom domains. كل تغيير في الموقع يحتاج تنفيذ الأمرين من جديد.
6. **تتبع النقرات (عند وجود روابط متاجر حقيقية):** في Supabase، Edge Functions، أنشئ الدالة `go` من الملف `backend/supabase/functions/go/index.ts`، وأوقف **JWT verification**، واضبط الأسرار `CLICK_SALT` و`SITE_URL`. أو من سطر الأوامر داخل مجلد `backend`: `supabase functions deploy go` (ملف الإعدادات `backend/supabase/config.toml` يوقف فحص JWT لها أصلًا). ثم ضع عنوانها (`https://<project>.supabase.co/functions/v1/go`) في `clickOutUrl` في ملفات `assets/config.js` الثلاثة؛ عندها يسجّل زر "زيارة المتجر" النقرة ثم ينقل الزائر للمتجر إذا كان للعرض رابط متجر.
7. **المهام المجدولة:** أضف أسرار GitHub المذكورة في القسم 3. المستورد اليومي (`import-feeds.yml`) والنسخة الاحتياطية الأسبوعية (`backup-db.yml`) يعملان من الفرع `main` فقط.

## 5. المهام اليومية
- **إضافة مدير:** يسجّل الشخص حسابًا في الموقع، ثم يستخدم المالك: الإدارة، الإعدادات، الفريق، دعوة عضو. الأدوار: owner (كل شيء)، catalog (المنتجات والأقسام وعمليات البحث الشائعة)، partners (المتاجر والكوبونات والخلاصات)، analyst (قراءة فقط مع قائمة المستخدمين).
- **إخفاء منتج أو إيقاف متجر:** الإدارة، المنتجات أو المتاجر. يختفي من الموقع فورًا.
- **تغيير أسعار الصرف وعمليات البحث الشائعة والكوبونات:** الإدارة، الإعدادات أو الكوبونات.
- **إضافة خلاصة متجر** (لا توجد شاشة لذلك بعد): أضف المتجر في الإدارة، ثم في SQL Editor:
  ```sql
  insert into public.feeds (store_id, format, schedule, url)
  values ('noon-sa', 'google_merchant', 'daily', 'https://example.com/feed.xml?key=${FEED_NOON_KEY}');
  ```
  الصيغ المدعومة: `xml` و`csv` و`json` و`google_merchant`. أضف السر إلى قائمة `env:` في الملف `.github/workflows/import-feeds.yml`.
- **المتاجر بلا خلاصة (قارئ صفحات المتجر):** الأسعار الحقيقية الحالية من eXtra وSaco وNahdi تأتي من قارئ صفحات المتاجر (يقرأ صفحات المنتجات المسموحة في ملف robots.txt للمتجر وبمعدل بطيء متعمّد). ربط المنتج بصفحة المتجر يتم في الجدول `scrape_pages`. التفاصيل خطوة بخطوة في `docs/STORE-INTEGRATION.md`.
- **تشغيل المستورد يدويًا:** GitHub، Actions، "Import store feeds"، Run workflow (ويمكن تحديد رقم خلاصة). تظهر النتائج في الجدولين `feed_runs` و`feed_rejects`.
- **تجربة ملف خلاصة دون حفظ شيء:** `node backend/importer/cli.js dry-run --file feed.csv --format csv --store noon-sa`.
- **طلبات الخصوصية والحذف:** تصل الطلبات إلى الجدول `privacy_requests` (يقرؤه المالك من SQL Editor أو Table Editor)؛ أجب خلال 30 يومًا كما يعد الموقع. يستطيع المستخدم المسجّل حذف حسابه من صفحة الملف الشخصي، ويُحذف معه مفضلاته وتنبيهاته.
- **تجربة الموقع المستضاف على هذا الجهاز:** `node scripts/build-site.js` ثم `node scripts/serve-dist.js` (يخدم `dist/` بترويسات الأمان نفسها الموجودة في الاستضافة).
- **تشغيل كل الاختبارات:** `cd backend && npm test` (لا يلزم تثبيت شيء).

## 6. استعادة نسخة احتياطية
1. GitHub، Actions، "Back up database"، افتح آخر تشغيل، ونزّل الملف المرفق `database-backup`.
2. فك التشفير: `openssl enc -d -aes-256-cbc -pbkdf2 -iter 600000 -pass env:BACKUP_PASSPHRASE -in doabno-DATE.dump.enc -out doabno.dump` (اضبط `BACKUP_PASSPHRASE` أولًا).
3. استعد إلى مشروع Supabase **جديد وفارغ**، ولا تستعد فوق مشروع يعمل دون حذر: `pg_restore --no-owner --no-privileges --dbname "<session pooler connection string>" doabno.dump` (عميل PostgreSQL 17). ثم وجّه `config.js` إلى المشروع الجديد.
4. **جرّب الاستعادة مرة واحدة قبل أن تحتاجها** على مشروع تجريبي. قد تحتاج استعادة جداول تسجيل الدخول (`auth`) إلى مشروع Supabase جديد إلى تعديلات بسيطة.
5. مشاريع الخطة المجانية ليس لها نسخ احتياطية يومية تلقائية، لذا فهذا الملف الأسبوعي هو شبكة الأمان. خطة Pro تتضمن نسخًا يومية.

## 7. تبديل المفاتيح
- **مفتاح الخدمة:** Supabase، Settings، API Keys: أنشئ مفتاحًا سريًا جديدًا، حدّث أسرار GitHub، ثم احذف القديم.
- **المفتاح العام:** نادرًا ما يلزم؛ أنشئ مفتاحًا جديدًا، حدّث ملفات `config.js` الثلاثة، أعد النشر، ثم احذف القديم.
- **مفتاح Resend:** أنشئ مفتاحًا جديدًا في Resend، حدّث سر GitHub، ثم احذف القديم.
- **مفتاح Gemini:** أنشئ مفتاحًا مدفوعًا جديدًا في Google AI Studio واستبدل سر `GEMINI_API_KEY` في Supabase. لا حاجة لتغيير الشيفرة.

## 8. ما هو حقيقي وما لا يزال تجريبيًا
**حقيقي:**
- الحسابات وتسجيل الدخول بالبريد، والمفضلة وتنبيهات الأسعار المحفوظة لكل حساب، وسجلات الموافقة، وطلبات الخصوصية، وحذف الحساب.
- لوحة الإدارة (دخول بأدوار، كل التعديلات محفوظة، سجل النشاط، المستخدمون، الفريق)، وإخفاء المنتجات وإيقاف المتاجر، وأزرار تُخفى حسب الدور (ويفحصها اختبار مقابل قواعد قاعدة البيانات).
- **أسعار حقيقية** من eXtra وSaco وNahdi عبر قارئ صفحات المتاجر (انظر `docs/STORE-INTEGRATION.md`)، والكتالوج يتوسع من صفحات eXtra وNahdi، مع صور المتاجر.
- **أُزيلت التقييمات وأعداد المراجعات ونسب انخفاض الأسعار التجريبية.** لا يعرض الموقع تقييمًا لم يأتِ من مصدر حقيقي؛ وانخفاضات الأسعار تُحسب من سجل الأسعار الفعلي.
- كود المستورد وتنبيهات البريد، وبناء الاستضافة، والنسخ الاحتياطية، والنشر على Cloudflare Pages تحت النطاق `doabno.com`.
- تطبيق iPhone (بناء مرفوع إلى TestFlight) وتطبيق Android (ملف APK تجريبي)، وإشعارات Android مُختبرة من البداية إلى النهاية.

**لا يزال تجريبيًا أو غير مكتمل:**
- **تتبع النقرات:** زر "زيارة المتجر" يسجّل النقرة فقط إذا كانت الدالة `go` منشورة وقيمة `clickOutUrl` مضبوطة وكان للعرض رابط متجر. روابط الأفلييت (مثل noon) تُنشأ يدويًا من لوحة الشبكة.
- **إعدادات لوحة الإدارة** محفوظة في قاعدة البيانات (الجدول `settings`، الهجرة 0012؛ المالك يعدّل والأدوار الأخرى تقرأ). أسعار الصرف وعمليات البحث الشائعة تصل الموقع فعلًا (من جدولين مستقلين). أما بقية الإعدادات (نص الصفحة الرئيسية، وضع الصيانة، روابط التطبيقين، الأسواق، البريد القانوني) **فالموقع العام لا يقرؤها بعد**، فتغييرها في الإدارة لا يغيّر الموقع حتى يُربط ذلك.
- **التقارير** (المشتريات، بلا شراء، استيراد التحويلات، وتصدير PDF بالطباعة): المشتريات من ملفات CSV للتحويلات ترفعها من الإدارة (`conversions`، الهجرة 0012)؛ و"الأكثر مشاهدة دون شراء" تحتاج `product_views` (0013). كلاهما فارغ حتى توافق الشبكات وتتوفر بيانات حقيقية.
- **أرقام الزيارات والإيرادات في الإدارة حقيقية لكنها صفر حتى تحدث نقرات** (تأتي من نقرات "زيارة المتجر" المسجلة مضروبة في تكلفة النقرة لكل متجر).
- رسائل انخفاض السعر مكتوبة ومختبرة لكن إرسالها يحتاج حساب Resend ونطاقًا. إشعارات Android تعمل؛ إشعارات iPhone تحتاج مفتاح APNs من Apple.
- **تسجيل الدخول بـ Apple وGoogle** موصول لكنه مطفأ: فعّل المزوّد في Supabase، ثم أدرجه في `socialLogin` في ملفات `config.js` الثلاثة فتظهر الأزرار (التفاصيل في `remainingthings.md`).
- **سياسة أمان المحتوى (CSP) معتدلة:** تمنع سكربتات المواقع الأخرى وتحدد وجهات البيانات، لكنها تسمح بسكربتات وأنماط مضمنة. إزالتها تسمح بسياسة أشد.
- **تحسين محركات البحث:** عناوين الصفحات تستخدم `#/` فلا تستطيع محركات البحث فهرسة صفحات المنتجات. الحل نقل الموقع إلى إطار يعرض الصفحات من الخادم (Next.js)، وهو قيد العمل في فرع منفصل.
- **تطبيق Android على Google Play وتطبيق iPhone على App Store:** لم يُنشرا بعد (يلزم حساب Play Console، وإكمال إجراءات App Store Connect).
- **الأسواق الخليجية الأخرى** (قطر، الكويت، البحرين، عُمان): معروضة بعبارة "قريبًا"، بلا متاجر ولا أسعار.
- **النصوص القانونية نصوص مؤقتة** ويجب أن يعتمدها المستشار القانوني للعميل قبل الإطلاق.

## 9. قائمة التحقق القانونية والخصوصية قبل الإطلاق
- رأي مكتوب من مستشار قانوني سعودي بشأن تخزين بيانات المستخدمين خارج المملكة (قاعدة البيانات الحالية في سنغافورة؛ ويسري نظام حماية البيانات الشخصية PDPL على بيانات المقيمين في السعودية أينما خُزنت). إن لزمت الاستضافة داخل السعودية فجداول المستخدمين (`profiles` و`favorites` و`alerts` و`privacy_requests` وتسجيل دخول Supabase) منفصلة ويمكن نقلها.
- سياسة الخصوصية والشروط وإخلاء المسؤولية وسياسة ملفات الارتباط والإفصاح عن الأفلييت، معتمدة ومنشورة. ويجب أن تذكر سياسة الخصوصية أن الصور المستخدمة في البحث بالصورة تُرسل إلى خدمة ذكاء اصطناعي، وأن الإشعارات تمر عبر Google وApple.
- جهة اتصال معيّنة بالاسم لطلبات الخصوصية.
- تُسجَّل الموافقة عند اختيار المستخدم خانة تنبيهات البريد أو التسويق (`alerts.consent_at` و`profiles.consent_at`). لا تُرسل الرسائل إلا لمن وافق.
- قبل استخدام المتجر في قراءة صفحاته: موافقة المستشار القانوني على قارئ الصفحات، والتزام قواعد `robots.txt` وشروط كل متجر.

## 10. التكلفة الشهرية
عند الإطلاق نحو **0 دولار بالإضافة إلى النطاق**. أول ترقيات واقعية: Supabase Pro بـ 25 دولارًا شهريًا وCloudflare Workers المدفوع بـ 5 دولارات، أي نحو **30 دولارًا شهريًا**؛ وResend Pro بـ 20 دولارًا شهريًا فقط فوق 100 رسالة تنبيه يوميًا؛ ومفتاح Gemini المدفوع حسب الاستخدام. الأسعار تتغير، فراجع صفحة كل مزوّد.
